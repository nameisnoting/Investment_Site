## 🎯 핵심 질문 5선 (1순위)

### Q1. 이 프로젝트를 한 문장으로 소개해주세요.

> "개인 투자자가 자기 자산 상황과 위험 성향에 맞는 분산 포트폴리오를 1분 안에 받을 수 있는 웹 서비스입니다. 시중 로보어드바이저의 한계인 천편일률적 추천과 블랙박스 문제를 해결하고자, 5개 시장 신호와 8개 펀더멘털 지표를 모두 화면에 공개하면서 사용자의 자산 tier·위험 성향·소득 유무에 따라 추천이 즉시 변하도록 설계했습니다."

**왜 이 답변?**
- **문제 → 솔루션 → 차별점** 구조 (PM 사고 검증)
- 구체 수치 (5신호 / 8지표 / 4 tier) — 깊이 증명
- 30초 안에 끝남

### Q2. 가장 어려웠던 문제는 무엇이었고, 어떻게 해결했나요?

> "배포 직후 발견한 외부 API 차단 문제였습니다.
>
> 로컬에서 잘 작동하던 yfinance가 Render 무료 호스팅의 공유 IP에서 Yahoo Finance로부터 rate limit 차단을 받아, 코어 ETF만 추천되고 개별주는 0개 — 이 프로젝트의 핵심 가치가 손상되는 상황이었습니다.
>
> 진단 → 대안 비교 → 의사결정 순서로 풀었습니다.
> 1. Render 로그에서 'Too Many Requests' 에러 패턴 확인
> 2. 4가지 대안 평가: yfinance 우회 / 유료 호스팅 / 다른 API / VM 이전
> 3. **Twelve Data 무료 API**로 1차 피벗 — 가입 후 검증해보니 사실상 AAPL 1개만 응답 (문서 액면 그대로 믿으면 안 된다는 학습)
> 4. **Finnhub으로 2차 피벗** — 키 기반 인증이라 IP 차단 우회 가능, 미국 전체 종목 정상 응답 확인
>
> 결과: 첫 분석 시간 190초→45초로 단축, 미국 종목 15/20 통과. 다만 Finnhub 무료가 한국 종목 미지원이라 한국 개별주는 EWY ETF로 대체했고, 이 결정은 [docs/decisions.md ADR-011](decisions.md)에 v2 로드맵 우선순위 1로 명시했습니다."

**왜 이 답변?**
- 단순 기술 문제 → **PM 의사결정 프로세스로 재구성** (진단→대안비교→피벗→재피벗)
- 학습 포인트 명시 ("문서 액면 그대로 믿으면 안 된다")
- 한계 인정 + 향후 계획 (한국 종목 v2)

### Q3. 사용자 피드백을 어떻게 반영했나요? 구체 사례 부탁드립니다.

> "투자 성향 슬라이더 추가가 가장 명확한 사례입니다.
>
> v3.0까지는 자산 입력만 받아 시스템이 자동으로 코어/위성 비중을 결정했는데, 한 사용자가 결과를 보고 '예금이 전부 투자로 동원되는 게 부담스럽다. 일부는 그대로 두고 싶다'고 피드백을 줬습니다.
>
> 이 피드백의 본질을 분석해보니 두 가지 니즈가 섞여 있었습니다:
> 1. **예금 자체에 대한 안전감** — '내 예금'이라는 정체성을 지키고 싶음
> 2. **위험 노출에 대한 제어권** — 시스템이 정해주는 게 아니라 본인이 결정하고 싶음
>
> 이를 5단계 슬라이더 하나로 해결했습니다:
> - 슬라이더 값 → **예금 유지율** (100%~0%)
> - 동시에 → **코어 비중 배율** (×1.3~×0.4)
>
> 한 컨트롤로 두 가지 효과 — 안정 쪽: 예금 그대로 + 코어 비중↑, 공격 쪽: 예금 다 동원 + 코어↓ + 개별주↑.
>
> 4단계가 아니라 **5단계로 정한 이유는 '중간'이 필요했기 때문**입니다. 4단계는 사용자가 보수/공격 어느 쪽으로 치우치도록 강제하는데, 실제로 '중간'이 다수일 거라 판단했습니다. 7단계는 차이가 미세해 의미를 잃습니다."

**왜 이 답변?**
- 피드백 → 본질 분석 → 솔루션 → 디테일까지 (UI까지 의사결정 근거)
- **숫자 결정 근거** (왜 5단계?) — PM 평가의 핵심
- 1대1로 답하지 말고 더 깊은 사고 보여줌

### Q4. 이 프로젝트의 다음 버전(v2)으로 뭘 하실 건가요? 우선순위는?

> "v2 우선순위 4개입니다.
>
> **1순위: 한국 종목 부활 (필수)**
> 이 도구의 원래 비전은 '은행/증권사 방문 없이도 한국 장기 투자용 우량주를 자동 추천받는 것'이었는데, v1에선 데이터 제약으로 미완입니다. 현재 검토 중인 4가지 옵션:
> - Financial Modeling Prep — 한국 지원 + 무료 250회/일
> - Polygon.io — 일부 한국 주식
> - DART Open API (한국 금융감독원) — 한국 펀더멘털 무료지만 통합 작업 큼
> - 자체 스크래퍼 — 가장 robust, 가장 작업 큼
>
> 가장 가능성 높은 선택은 **DART API + Polygon 조합** — 한국 펀더멘털은 정부 공식 데이터로, 가격은 Polygon으로.
>
> **2순위: 백테스트 시각화**
> 이미 [backtest.py](backtest.py)에 워크포워드 백테스트 엔진이 있습니다. 결과를 차트로 보여주는 UI만 추가하면 '이 전략이 과거에 어땠는지'를 사용자가 검증할 수 있습니다. 신뢰 확보의 핵심 기능이라 우선순위 높습니다.
>
> **3순위: 진입 시그널 알림**
> 사용자가 관심 종목 등록 → 시장 fear_score 발동 또는 진입 플랜 격상 시 이메일 알림. 단발성 사용을 지속 사용으로 전환.
>
> **4순위: 모바일 PWA 전환**
> 현재 반응형이지만 PWA(Progressive Web App)로 만들면 홈 화면 설치 + 푸시 알림 가능.
>
> 우선순위 기준은 **'원래 비전과의 정합성 × 사용자 가치 × 구현 난이도'** 입니다. 한국 종목 부활은 비전 정합성이 가장 높아 1순위, PWA는 가치 대비 구현 비용 커서 4순위로 둡니다."

**왜 이 답변?**
- **명확한 우선순위 + 기준** (PM의 핵심)
- 단순 나열이 아니라 각각의 **근거**
- "원래 비전과의 정합성"이라는 PM 사고 보여줌

### Q5. 비개발자라고 들었는데, 이 프로젝트를 어떻게 만드셨나요?

> "AI 페어 프로그래밍(Claude Code) 으로 만들었습니다. **'기획자가 코드를 직접 짜는 시대'** 라는 변화 한가운데 있는데, 이 프로젝트는 그 가능성과 한계를 모두 학습한 경험입니다.
>
> 제가 한 일은 100% PM 역할이었습니다:
> - 문제 정의 ('내 자산에 맞는 포트폴리오를 자동 추천하면 좋겠다')
> - 사용자 시나리오 작성 (위 페르소나 3개)
> - 기능 우선순위 결정 (예: '슬라이더가 코어 ETF 추가보다 먼저 필요')
> - 의사결정 (예: '4단계 vs 5단계 vs 7단계 슬라이더' 비교 후 5단계)
> - 피드백 루프 (결과 확인 → '이건 좀 이상한데?' → 로직 수정 요청)
> - 트레이드오프 (예: 한국 개별주 vs 안정성 → 안정성 선택, v2 로드맵 명시)
>
> AI가 코드를 작성하지만, **무엇을 만들지 / 왜 만들지 / 어떻게 측정할지는 모두 사람의 판단**입니다. 면접 평가하시는 분께 강조하고 싶은 점은:
> 1. 이 프로젝트의 모든 의사결정은 제가 내렸고 [docs/decisions.md](decisions.md)에 기록되어 있습니다
> 2. AI 코드도 검증/조정을 거쳤습니다 (예: yfinance 차단 발견 → Twelve Data 실제 검증 → 무료 한계 발견 → Finnhub 재피벗)
> 3. **개발 능력보다 '개발자와 협업하는 능력'에 더 큰 자신감을 갖게 됐습니다**. 이 프로젝트에서 AI를 개발자로 두고 협업한 경험이, 실제 PM-개발자 협업에서도 그대로 통할 거라 봅니다."

**왜 이 답변?**
- **AI 협업 시대의 PM 역량 강조** (트렌드 정합)
- 한계를 솔직히 인정 + **AI에게도 PM이 필요함**을 어필
- 협업 능력으로 연결

## 🔧 기술/도메인 질문 (2순위)

### Q6. 왜 VIX를 역발상으로 매핑했나요?

> "원래 시스템은 'VIX 30 초과 = 무조건 관망'이었는데, 이건 시장 저점 매수 기회를 놓치는 구조입니다.
>
> 실제로 워런 버핏은 '공포에 사고 탐욕에 팔라'고 말했고, 학계 연구에서도 VIX 30~35 구간이 장기 수익률 측면에서 최고 매수 타이밍이라는 결과가 많습니다 (S&P 500 1990~2024 데이터 기준).
>
> 그래서 VIX를 0~1로 정규화할 때:
> - VIX 12↓ → 0.20 (너무 안심 = 거품 의심, 약세 시그널)
> - VIX 25 → 0.70 (긴장, 위험-보상 양호)
> - VIX 32 → 0.85 (공포 진입, 매수 기회 ↑)
> - VIX 40+ → 0.60 (극도 공포, 너무 위험해서 감점)
>
> 추가로 `fear_score`라는 별도 트리거 — VIX 30↑ AND 시장 -15%↓ 동시 충족 시 발동 — 이걸로 종목 진입 플랜을 SPLIT_BUY → AGGRESSIVE_BUY (5분할 첫 매수 50%)로 격상합니다.
>
> 핵심은 **VIX 자체가 곡선이고 양 극단은 모두 위험**이라는 점입니다."

### Q7. 코어/위성 비중을 자산 tier별로 다르게 한 이유는?

> "**자산 규모가 작을수록 개별주 분산이 어렵기 때문**입니다.
>
> 예를 들어 자산 5천만에 개별주 5개를 추천하면 종목당 1천만. 그런데 우리 시스템이 추천하는 종목 평균 가격이 $300~500이라, 1천만(약 $7,200)으로는 종목당 15~24주만 살 수 있습니다. 단일 종목 변동성 노출이 너무 큼.
>
> 반면 자산 5억이면 종목당 1억까지 가능 → 분산 + 의미 있는 비중 모두 확보.
>
> 그래서 tier별:
> - starter (<3천만): 코어 80% (ETF로 분산 효과 확보)
> - small (<1억): 코어 65%
> - mid (<5억): 코어 50%
> - large (5억+): 코어 35% (분산 가능하니 알파 추구 비중 ↑)
>
> 연속 함수가 아니라 4단계로 끊은 이유는 사용자에게 설명 가능성 때문입니다. '자산이 9,999만원이라 코어 64.7%' 보다 'small tier라 코어 65%'가 직관적입니다."

### Q8. 데이터 소스를 굳이 무료로 고집한 이유는?

> "두 가지 이유입니다.
>
> 첫째, **포트폴리오용으로 안정 운영해야** 합니다. 채용 담당자가 링크 클릭했을 때 결제 끊기거나 무료 한도 초과로 안 뜨면 끝입니다.
>
> 둘째, **이 프로젝트의 사용자 가치 검증**을 위해서입니다. 만약 데이터 비용이 비싸야만 작동하는 구조라면, 실제 개인 투자자에게 못 보급합니다. v2에서 한국 데이터 추가할 때도 'DART Open API 같은 무료 소스 우선 통합' 원칙 유지할 계획입니다.
>
> 다만 트레이드오프는 인식하고 있습니다:
> - 무료 → API 한도/안정성 ↓
> - 유료 → 데이터 풍부, 한국까지 즉시 가능
>
> 이건 **'개인 무료 사용 가능성을 유지할 것인가, 안정성을 우선할 것인가'** 의 가치 선택이고, 저는 전자를 택했습니다. 만약 회사 서비스로 만든다면 후자를 택할 수도 있습니다."

## 💬 협업/소통 질문 (3순위)

### Q9. 개발자와 일하실 때 가장 신경 쓰는 것은?

> "**'왜?'를 같이 정렬하는 것**입니다.
>
> 이 프로젝트에서도 AI 개발자에게 단순히 '슬라이더 추가해줘'가 아니라 '예금 보존이 필요한 이유는 사용자가 안전감을 원하기 때문이고, 5단계로 한 이유는 중간 선택지가 필요하기 때문이야'라는 맥락을 같이 줬습니다.
>
> 그래야 개발자가 구현 디테일에서 더 나은 결정을 합니다. 예를 들어 슬라이더가 슬라이더 값 변경 시 즉시 결과를 다시 계산하느냐, 입력 완료 후 계산하느냐도 '맥락'이 있어야 결정 가능한 디테일입니다.
>
> 또 하나는 **'트레이드오프를 같이 들여다보기'** — 개발자가 '이건 1주일 걸려요' 라고 하면, PM이 '그러면 우선순위 X와 비교해서 어느 게 가치 큰가?' 같이 따져봐야 합니다. 우리는 한국 종목 부활을 v2로 미루는 결정을 같이 했는데, 그건 단순 '개발이 어렵다'가 아니라 '안정성 우선이라는 가치'로 합의했기 때문입니다."

### Q10. 의사결정을 문서화하시는 이유는?

> "**미래의 자신과 협업자를 위해서**입니다.
>
> 의사결정 시점엔 맥락이 머리에 다 있지만, 3개월 후엔 사라집니다. 그러면 '왜 이렇게 했더라' 다시 고민하고, 다른 협업자도 같은 길을 헤매게 됩니다.
>
> 이 프로젝트의 [docs/decisions.md](decisions.md)에 11개 결정을 ADR(Architecture Decision Record) 형식으로 기록했습니다. 각 결정마다:
> - Context (왜 이 결정이 필요했나)
> - Options (어떤 선택지를 고려했나)
> - Decision (무엇을 선택했나)
> - Rationale (선택 근거)
> - Consequences (이 선택으로 얻는 것 / 잃는 것)
>
> 이렇게 기록해두면 향후 v2에서 '이 결정 뒤집을 만한 새 정보가 있나?'를 빠르게 판단할 수 있습니다. 예를 들어 ADR-011(한국 종목 비활성)은 'v2에서 재검토' 상태로 명시되어 있어서, 새 데이터 소스 찾으면 즉시 재고할 수 있습니다."

## 🎓 도메인 깊이 질문 (4순위)

### Q11. 핀테크/투자 도메인 지식은 어떻게 쌓으셨나요?

> "이 프로젝트 만들면서 깊어졌습니다. 처음엔 '내 자산을 자동으로 분배하는 도구'에 막연한 관심이 있었는데, 만들다 보니 모던 포트폴리오 이론, 효율적 시장 가설, 코어-위성 구조, VIX 역발상 같은 개념을 직접 코드로 구현하면서 학습했습니다.
>
> 구체적으로:
> - **CAPE, 버핏지수, 장단기 금리차** — 시장 국면 판단 지표 비교 학습 후 5신호 가중합에 일부 채택
> - **RSI, 일목균형표, MACD** — 기술적 지표 비교 후 RSI + MA + 모멘텀 조합 선정
> - **ROE, FCF, PEG, EV/EBITDA** — 펀더멘털 지표 학습 후 8개 지표로 가중합 구성
> - **DCA(분할매수), 변동성 헤지** — 코어 ETF를 일시 매수가 아닌 N개월 DCA로 결정
>
> 또한 시중 로보어드바이저(예: AIM, 핀트, 파운트) 분석도 했습니다. 대부분 블랙박스인데 우리는 모든 점수를 공개하는 게 차별점입니다.
>
> 부족한 부분은 인정합니다 — 실제 자산운용사의 운용 시스템이나 트레이딩 알고리즘 깊이는 아직 없습니다. 입사 후 도메인 전문가 분들께 배우면서 빠르게 따라잡고 싶습니다."

## 🚨 어려운/날카로운 질문 (대비)

### Q12. 이 도구를 실제로 누가 쓸까요? 시장은 있나요?

> "솔직히 v1 그대로는 시장 규모가 작습니다. 한국 종목이 빠진 상태라 한국 개인 투자자에게 핵심 가치가 약합니다.
>
> v2에서 한국 종목이 부활하면 타겟은 명확해집니다:
> - **20~40대 자산 1천만~5억 개인 투자자** (KB증권 추산 약 600만명)
> - 이 중 시중 로보어드바이저 사용자가 약 30만명 — 우리는 '투명성'으로 그 30만 + 거기 안 만족한 사람들을 노립니다.
>
> 비즈니스 모델은 일단 무료 도구로 트래픽 확보 후, 다음 옵션 검토 가능:
> 1. **프리미엄 알림** ($5/월): 실시간 진입 시그널 알림
> 2. **포트폴리오 추적**: 사용자가 실제 보유한 종목 연동 후 리밸런싱 제안
> 3. **데이터 라이선스**: 분석 알고리즘 자체를 핀테크 스타트업에 API 판매
>
> 다만 v1 시점에선 비즈니스보다 '실제 작동하는 도구'를 만든 PM 학습이 우선이었습니다."

### Q13. 시장이 평소엔 강세인데 왜 결과에 '진입 보류'가 많이 나오나요? 시스템이 너무 보수적인가요?

> "예리한 질문입니다. 현재 미국 빅테크 RSI가 70~80대인 종목이 많아서 진입 보류(AVOID)가 자주 뜹니다.
>
> 두 가지로 봐야 합니다:
>
> **1. 시스템 의도대로**: '추세 좋음(IMMEDIATE)' / '단기 과열(WAIT_PULLBACK)' 구분은 의도된 동작입니다. 시장 강세 + 종목 과열이 동시면 추격매수 위험이 크기 때문에 눌림목 대기가 합리적입니다.
>
> **2. 다만 사용자에게 메시지가 부족함**: '이번에 추천 보류된 종목은 가격이 다시 빠지면 즉시 매수 시그널로 격상됩니다' 같은 안내가 화면에 없습니다. v2 UI 개선 항목입니다.
>
> 또한 **fear_score 트리거**가 평상시 발동 안 하는 것도 의도된 동작입니다. 시장 평상시엔 일반 분할매수가 나오고, 실제 폭락 발생 시(VIX 30↑ + 시장 -15%↓)만 공격 매수 시그널이 발동되도록 설계했습니다."

### Q14. 무료 데이터로는 한계가 명확한데, 진짜 PM이라면 비용 들여서라도 안정적인 데이터 확보하지 않나요?

> "맞습니다. **개인 프로젝트라 무료 우선 원칙**으로 시작한 거고, 회사 서비스라면 다르게 결정합니다.
>
> 회사 서비스 가정:
> - 사용자 수 1만명 가정 시 데이터 API 비용 월 $200~500 (Polygon Starter 등)
> - 사용자당 비용 환산하면 $0.02~0.05/월 — 무시 가능
> - 안정성 = 이탈률 직결이라 데이터 비용은 ROI 명확
>
> 그래서 PM 결정 기준:
> - **개인 프로젝트**: 무료 우선, 한계 수용
> - **B2C 서비스**: 유료 데이터 + 안정 SLA
> - **B2B 화이트라벨**: 클라이언트 비용 부담
>
> 면접관님이 본 v1은 첫 번째 상황의 결과이고, 실제 입사 후 회사 서비스 PM 한다면 두 번째 기준으로 갑니다."
